## 3. THE HIGH finding — Needleman–Wunsch evidence miskeying

**PERSISTS, unchanged, in the post-change-set tree.** **`src/hannom/textdiff.py` lines ~365–371** build `readings_by_index`/`sources` keyed by **absolute** position in the Nôm string.
**`_score` (lines ~408–428) and the traceback (the backtracking `while` loop, lines ~461–471 — `matched.add` at ~465) and the main flush loop (lines ~535–543) use list index** (`i‑1`), not the absolute position:

```python
def _score(char_index, token_index):
    rs = readings_by_index.get(char_index)   # BUG: char_index is 0..n-1 list index
...
source = sources.get(i - 1, "")              # BUG again in traceback
...
for char_index, char in chars:               # char_index is ABSOLUTE position
    if char_index in char_matches:           # BUG: char_matches keys are list indices
        flush_run(char_matches[char_index])
```

(`all_positions` at ~:490 is dead — never used; flagged in the original audit, still unused.)

Any 1‑1 row containing a non‑ideograph (private‑use codepoints `U+F0xxx` from the Kim Hán Nôm font, punctuation, spaces, `[MASK]`) before a candidate ideograph shifts list‑index ≠ absolute‑position for all downstream chars. Effects:

- evidence for later chars is looked up at the wrong absolute position → usually **missed** (readings lost → char treated as unknown/unmatchable) or **wrong char's readings attached** (fabricated anchor — a character gets credited on the strength of another character's evidence);
- `char_matches` (list‑index keys `0..n‑1`) compared against absolute positions in the flush loop ⇒ anchors attach to the wrong characters and elements get built over the wrong positions.

**New in the revised tree (revised 2026-11-12):** the miskeyed `readings_by_index` is shared by the **variant fold** tier (§3A) — fold cells built on miskeyed readings feed `_score > 0` matched anchors exactly like exact/flat cells, so the miskeying now corrupts the fold tier's evidence too, and the fold tier widens the anchor set that can suppress or shift error runs. Fix priority goes **up**, not down (R2).

## 3A. THE VARIANT FOLD — a default-on weak anchor tier (NEW 2026-11-12; the headline change of this revision)

The 2026‑11‑12 change-set added a weak, accent/orthography‑insensitive match to `textdiff` (and it was already present in `charalign` for the alignment pass). Mechanism:

- `textdiff.py:27`: `from .charalign import fold as variant_fold`.
- `charalign.fold` (textdiff imports it; defined ~:53–67; `_Y_AS_I_RE` at :46): NFD → casefold → strip `Mn` (tone marks) → `đ→d` → final‑form `y→i` via the regex `(qu|[bcdghklmnprstvx]{0,3})y` under `.fullmatch` (`quỷ/quỉ/quĩ/quy` → `qui`; `kỷ/kỳ` → `ki`; `mỹ/sỹ` → `mi/si`) → `gi→d` prefix alternation (`giấu` → `dau` ≡ `dấu`). Applied to **comparisons only** — stored cell text is **never** rewritten.
- **Score weight: 1.0** — a *weak* match, same tier as the opt‑in flat tone‑stripped match, **never 2.0 (exact), never strong**.
- Where it fires (two locations):
  1. `_reading_match` (textdiff.py:274–312): a fold comparison clause is appended **unconditionally** after the exact and flat clauses (lines :307–311). **`_reading_match` itself is DEAD CODE — zero callers in `src/` or `tests/` (re-verified 2026-11-12).** Its docstring still claims *"Diacritic-stripped matching is only used when `allow_flat` is set"* — stale doc for a clause that ignores `allow_flat`. Should be removed or wired.
  2. `_score` — the inner NW cell (textdiff.py:424–428), gated by `allow_variant_fold`, whose default is **`True`** (~:324) and which **both call sites omit** (`align.py:528`, `orchestrator.py:339`) ⇒ the fold is **ALWAYS ON** wherever `auto_text_diff` runs. By contrast the flat tone‑strip cell remains opt‑in at align time (`allow_flat_match=False` default; `align.py:528` passes none) while the recompute path keeps `allow_flat_match=True` — the pre‑existing align/recompute asymmetry, now layered with an always‑on second weak tier (see §5.B).
- **It is an anchor tier, not a neutral cell.** Matched anchors in the backtrack are exactly the cells with positive score (`if _score(i - 1, j - 1) > 0: matched.add(i - 1)`, textdiff.py:~464–466). A fold 1.0 cell therefore **anchors** just like flat/exact cells and, like them, **can suppress or shift error runs** (an unmatched run is flushed only up to the next anchor; a fold anchor splits or swallows a would‑be error element, or extends a suppressed span past punctuation). Refutation, explicit: the conclusion (implicit in §6 of this report pre‑revision, and stated in the first audit's sentinel list as "anchorable = exact or flat") that anchors cannot suppress errors by themselves is **false for the fold tier** — fold anchors suppress/shift error runs while never rewriting stored text. The "error spans suppress" taxonomy must be re-read with **three** weak/strong tiers (exact 2.0 > flat 1.0 opt‑in > fold 1.0 default‑on); zero‑score cells remain non‑anchoring, so unknown evidence still cannot fabricate reds (§6).
- **Live confirmation (read‑only probe, 2026-11-12):** with `FakeLexicon{'鬼': ['quỷ']}` and default flags, `auto_text_diff('鬼', 'qui')` → `elements=[]`, flags `['DIFF_NO_READING_MISMATCH']` (fold cell anchors; mismatch **suppressed**). Same for `quĩ`, `quy` → `qui`; `kỷ`/`kỳ` → `ki`; `giấu` → `dấu`. With `allow_variant_fold=False` the rows revert to red elements with `DIFF_READING_MISMATCH`. Stored `ch_txt`/`vi_txt` are untouched in all cases.
- **`configs/alignment.yaml` carries `text_diff.variant_fold: true`** (~:42) with the comment *"Report coverage in the metrics so reviewers can audit how often it fires"*. **That key is DEAD CONFIG:** `configs/alignment.yaml` *is* loaded into `project.alignment_config` (`config.py:214`) and passed to the align stage (`orchestrator.py:411`), but the `text_diff.variant_fold` key is **never read by any code path** (grep re-verified 2026-11-12: only `t1_map` reads `alignment_config["alignment"]`; nothing reads `["text_diff"]`). No metric, counter, or log records fold firings; **the promised auditability does not exist**. The fold's default‑on status comes solely from the function signature, not from this yaml.
- **No test exercises the fold cell.** The only fold test (`tests/test_charalign.py::test_fold_handles_old_spellings_and_ocr_tone_slips`) tests `charalign.fold` itself; nothing covers `auto_text_diff`'s `allow_variant_fold=True` path. All 282 tests pass despite this coverage hole.
- **`docs/decisions.md` (2026‑11‑12 entry) calls the fold "a 1.0-cost NW cell like the flat tone-stripped match"** — loose phrasing: `textdiff` is the 1‑1 scorer/NW‑cell owner (the fold implementation lives in `charalign` but the cell and the threshold live in `textdiff`), and the fold is **default‑on** vs the flat match's opt‑in — they are not "like" each other in policy terms. Report decisions.md errata to the docs owner (§7 R11).
- **Consequences for this area:** F's sentinel list ("anchorable = exact or flat") is **obsolete** — anchors now include the variant fold; §3 miskeying propagates into fold evidence (§3); metrics and histograms reflect the fold already (all `text_diff` outputs were regenerated by the rebuilt align); the fold's blast radius on the gate is unmeasured and unauditable today (§5.G, §7 R11).
