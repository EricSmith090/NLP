# Decisions and guideline deviations

- **One ZIP with three book folders** is an extension of guideline v2.1 §Quy định chung về dữ liệu nộp (one book per ZIP). `hannom split` produces per-book ZIPs if instructors require the one-book form.
- **OCR: Kim Hán Nôm API first, local fallback on quota (api_mode `api_first`).** Changed 2026-11-08 from the earlier local-majority + API-second-opinion routing. The API is primary for Nôm pages per the guideline's ưu tiên; when the 25/min, 50/h, 200/day, 600/week quota is exhausted (or the API cannot serve a page), the pipeline switches to the local models. Local-fallback results are written to `data/ocr/<book>/local_fallback/<page>.json` so they never clash with API-handled `data/ocr/<book>/<page>.json`; `load_result` prefers the API file. Quốc ngữ stays on Vintern-1B-v2 (the API cannot OCR QN). Router uses `QuotaExceeded` as the switch signal.
- **Dictionary: unknown → review, never auto-red.** Guideline p.16 would red a character absent from all delivered dictionaries after online checks. The codebase routes unknowns to review because hvdic/dv crawls are incomplete (dictionary spec Hạn chế đã biết) and online lookup is a manual step. Yellow is never auto-generated.
- **Reading-system filtering:** Entry/v1 “Không suy đoán” — only `qn/hv/nom` systems are QN evidence; pinyin/jyutping/on/kun/hangul are gloss only.
- **Diacritic matching:** exact-first; stripped matching is opt-in (`strip_diacritics_for_reading_match: false` by default).
- **Book 3 OCR refresh, 2026-11-08:** all 110 targets re-OCR'd after archiving the buggy old drafts. QN (60 pg) = Vintern-1B-v2; Nôm (50 pg) = Kim Hán Nôm API first: initially 40 served (17 from cache, 23 fresh) and **10 pages fell back to paddleocr_vl** because the hourly cap (50/h) tripped at ~15:00 UTC. Later on 2026-11-08 the 10 pages were re-served by the API on the automatic hour-refill re-serve (~16:00 UTC, 28 fresh calls); the paddle drafts are archived in `data/archive/b3_refresh_2026-11-08/local_fallback_pre_reserve/` and are unused. Final coverage: 50/50 Nôm API (all `http_200`), 60/60 QN Vintern. `local_fallback/NOTE.md` holds the full provenance. Books 1/2 still need an explicit quota policy (their Nôm sections alone exceed the remaining weekly budget).
- **Vintern full-page silent failures (0016/0032/0040/0056), fixed 2026-11-09:** Vintern-1B-v2 returned only the page-number header on 4 of 60 QN pages (verified identical in both the archived and fresh runs — a model/layout limitation, not a rate or token issue). `hannom.ocr.local_vintern.VinternEngine` now falls back to three horizontal bands when the full-page output is under 40 characters and adopts the band result only when decisively longer (title pages are protected); the retry is recorded as `raw.band_retry` + `BAND_RETRY_AFTER_FULLPAGE_FAILURE` in warnings. Their broken cache entries are preserved in `data/archive/b3_refresh_2026-11-08/vintern_empty_fullpage/`.
- **Running header/footer never stripped by `clean`, fixed 2026-11-09:** the cross-page running-line detector produced `running_lines={ch:0, vi:0}` because full-page Vintern emits a single line per page, so the page marker (`-10 ( 113 )` etc.) and the `Sửa Lưới` book-title footer leaked into the cleaned text of every page. `clean.py` now strips (i) narrowly-matched leading page markers and (ii) the literal book-title footer (never blanking a page down to nothing), each logged as `PAGE_MARK_REMOVED`/`FOOTER_TITLE_REMOVED` with counts. Content pages carrying only a trimmed marker keep their footer so nothing silently disappears.
- **Co-segmentation for dịch âm 1-1 rows (2026-11-09):** `src/hannom/cosegment.py` splits Nôm+QN of an image-map pair at the QN sentence punctuation and assigns Nôm characters to each sentence proportionally (this translation keeps nom_len ≈ tok_len, ~0.93–0.98 ratio across pages). Produces sentence-scale 1-1 chunks with a COSEGMENTED flag; falls back to the old fragment splitter when a page has too little text or no boundaries. Enabled by default in `build_segments`. Influence measured on pilot pages 116/115/100: clean sentence correspondence matching the translation (e.g. “trộm cướp…” ↔ 盗刼𥙩…); reading-level DP matcher is weak on this book (~13–20% known-reading recall) but the 1-1 structure is recovered from VI punctuation + ratio assignment; boundaries still go through the review app.
- **Image map:** `<Tên sách>_image_map.json` is optional per guideline; missing is a warning, invalid is a blocker. Empty-side pairs represent scan-missing pages (missing/ch ↔ vi empty, missing/vi ⇒ ch empty).

- **2026-11-09 repair branch `repair/pipeline-audit-2026-11-09`:** review metadata persisted to `<Name>.review_metadata.jsonl` sidecar (CSV keeps the stable 5 columns; missing/dup/mismatch detected, flagged `REVIEW_METADATA_MISSING/MISMATCH`); alignment DP gained explicit `UNMATCHED_NOM`/`UNMATCHED_QN` skip transitions with configurable penalties and honest status flags; co-segmentation boundaries are derived from windowed reading anchors (COSEGMENTED_ANCHORED) with the proportional cut only as an explicitly flagged fallback (COSEGMENTED_UNANCHORED, never trusted as verified evidence); textdiff uses union of lexicon + dictionary readings and flags ambiguous evidence (DIFF_AMBIGUOUS_READINGS); evaluation reports accuracy over verified rows separately from coverage (INSUFFICIENT_COVERAGE/UNVERIFIED_RATIO_HIGH/EXCESSIVE_NULL_ROWS block the gate, `minimum_coverage` 0.9 / `max_unverified_ratio` 0.05 defaults in configs/project.yaml, documented policy); OCR BAND_RETRY_AFTER_FULLPAGE_FAILURE is promoted to page review flags; image_map pairs carry mapping confidence/source/status with anchor-evidence verification, manual corrections via image_map.manual.json, unknown statuses become unresolved. - **2026-11-09 second repair pass (repair/pipeline-audit-2026-11-09, on top of 3d8e4f2):** review decisions are first-class durable records in `data/review/<book_id>.review_decisions.jsonl` (append-only; explicit `accepted_match`, `accepted_difference`, `alignment_reviewed`, `unresolved`, `unmatched`, `rejected`, `content_edited`; hash-bound to the row content at decision time; stale decisions never verify; content edits never approve; a no-change acceptance persists through the review app). The evaluator distinguishes verifying decisions from automatic evidence; `HUMAN_REVIEWED` is no longer honored anywhere. Lexicon learning requires an explicit verifying decision with positional evidence — a reviewer character-to-token mapping, or a single Nôm character + single accepted QN token; dictionary membership in the sentence never learns. Reading anchors require strict local uniqueness in both directions (repeated readings or competing characters never anchor); image-map verification requires ≥ 2 unique anchors at ≥ 50% coverage. Alignment `confidence` is now documented as structural grouping confidence; `semantic_confidence` (unique-anchor coverage) is reported separately and `ALIGN_EVIDENCE_INSUFFICIENT` marks rows without reading evidence. Metadata integrity failures and decision-log failures are gate-blocking (`METADATA_*`, `REVIEW_DECISION_*`, `DECISION_*` prefixes); the metadata sidecar write is atomic (temp file + fsync + os.replace) with schema and confidence (type/finiteness/range) validation.
- **2026-11-09 third repair pass (repair/pipeline-audit-2026-11-09, on top of e0107ec):** decision events replay in append/file order; the latest event determines the row state — stale/invalid/conflicting latest events never verify and never fall back to older approvals; superseded historical records stay in the append-only log without creating active blockers; genuine same-revision contradictions (match vs difference verdicts, or same Nôm position mapped to different tokens) are `REVIEW_DECISION_CONFLICT` (gate-blocking); ordinary status transitions are legitimate. Dictionary learning fails closed: log-wide integrity failures disable learning for the book; row-specific failures exclude only the affected row; verified-but-superseded or conflicted rows never learn. Learning is idempotent — identical reviewer provenance is not learned twice. The metadata sidecar persists both `confidence` (structural) and `semantic_confidence` (unique-anchor coverage) with `[0,1]` finiteness validation; missing keys load as absent. Positional mapping sets validate atomically: uniqueness of Nôm and QN token position assignments, monotonic order, exact content checks — one invalid mapping rejects the set.
- **2026-11-09 fourth repair pass (repair/pipeline-audit-2026-11-09, on top of 1a35824):** decision replay now distinguishes active failures (latest event only; blocking) from historical audit diagnostics (preserved in a separate `audit` channel; never gate-blocking). Malformed/stale/conflicted latest events still block evaluation, learning and alignment; log-wide failures block the whole book and disable learning; superseded diagnostics surface in `BookMetrics.decision_audit_diagnostics`. Mapping deserialization is strict and atomic (genuine JSON ints, no booleans/floats/strings; non-list `character_token_mappings` rejects the whole record; every non-object entry rejects the record); every mapping set is validated against the current row's content before a decision may be `valid`. CI now triggers on `repair/**` branch pushes as well as dev/main and PRs.
